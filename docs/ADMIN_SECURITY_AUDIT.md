## 🔴 Критично (обязательно к исправлению)

### C1. Бэкдор в сессии: вход без пароля значением куки `optics_admin=1`
**Где:** `lib/admin/auth.ts:28`, `app/admin/layout.tsx:14`, `middleware.ts:17`;
установка куки — `lib/admin/auth.ts:65` (`ADMIN_SESSION_SECRET || "1"`).

**Суть:** значение сессионной куки — это либо секрет из env, либо строка `"1"`.
Все три места проверки принимают `"1"` **безусловно**. `ADMIN_SESSION_SECRET`
нет даже в `.env.example` → на проде кука почти наверняка буквально `"1"`.

**Эксплойт (проверьте сами на текущем проде):** открыть сайт → DevTools →
консоль → `document.cookie = "optics_admin=1"` → перейти на `/admin/dashboard`.
Полный доступ без логина: удаление товаров, изменение/отмена заказов, **создание
реальных ТТН Новой Пошты**, загрузка файлов, пере-сев каталога.

**Почему серьёзно:** даже если задать сильный `ADMIN_SESSION_SECRET`, приём
`"1"` зашит в коде и продолжит работать — «секрет» не защищает.

**Как чинить:**
1. Сделать сессионную куку **неугадываемым подписанным токеном** (HMAC-SHA256
   от payload `{iat, exp}` серверным секретом). Проверять подпись и срок и в
   `hasAdminCookie`, и в `middleware`, и в `layout`.
2. **Убрать все `value === "1"`** проверки.
3. Middleware работает на Edge — использовать Web Crypto (`crypto.subtle`,
   async), не Node `crypto`.
4. Требовать `ADMIN_SESSION_SECRET` в проде; при отсутствии — не пускать
   (fail-closed), а не подставлять `"1"`.

### C2. Сид-эндпоинт с угадываемым дефолтным секретом
**Где:** `api/admin/seed/route.ts:12` — `SEED_SECRET || ADMIN_SESSION_SECRET || "seed-once"`.

**Суть:** если env не задан, любой запрос с заголовком `x-seed-secret: seed-once`
запускает пере-сев каталога в Supabase (перезапись данных владельца).

**Как чинить:** требовать реальную админ-сессию (после фикса C1) **или** явно
заданный `SEED_SECRET`; убрать дефолт `"seed-once"`; лучше вынести сев в CLI-скрипт,
а не в публичный route.

### C3. Дефолтный пароль и демо-креды на экране логина
**Где:** `lib/admin/auth.ts:11` (`admin123`), `.env.example:12`
(`change-me-in-production`), `app/admin/page.tsx:99-105` (показывает
`admin@pro-optics.ua / admin123` прямо в форме), а поле email предзаполнено.

**Как чинить:** убрать демо-подсказку и предзаполнение на проде (оставить только
в dev), требовать смену пароля при первом входе, задать сильный `ADMIN_PASSWORD`.

## 🟡 Средний приоритет

### M1. Загрузка файлов без валидации
**Где:** `api/admin/upload/route.ts`. Принимает любые файлы любого размера, тип не
проверяется (только `content-type: multipart`). Риск: заливка не-картинок,
огромных файлов.
**Чинить:** whitelist MIME (`image/jpeg|png|webp|avif`), лимит размера (напр.
≤8 МБ), лимит количества, при желании — ресайз/сжатие.

### M2. Нет CSRF-защиты на мутациях
Куки `sameSite=lax` частично защищают, но для админки стоит добавить проверку
`Origin`/`Referer` (тот же сайт) или CSRF-токен на POST/PUT/PATCH/DELETE.

### M3. Дашборд беден
Есть счётчики (товары, новые заказы, склад). Для «профи» добавить: выручка за
период, список последних заказов, топ-товары, мини-график продаж.

### M4. Единый гвард для API-роутов
Каждый route вручную зовёт `requireAdminApi`. Легко забыть в новом эндпоинте.
Стоит вынести в общий helper/матчер, чтобы защита была по умолчанию.
