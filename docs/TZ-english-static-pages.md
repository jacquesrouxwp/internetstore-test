## 2. Две формы перевода, и почему страницы в разном состоянии

**`oferta` и `privacy`** уже переведены на хелпер. В начале компонента:

```tsx
const loc = locale as Locale;
const ru = loc === "ru";
const en = loc === "en";
// Third argument is optional: a page still being translated falls back to
// Ukrainian rather than rendering an empty slot.
const L = (
  uk: React.ReactNode,
  ruText: React.ReactNode,
  enText?: React.ReactNode,
): React.ReactNode => (en ? (enText ?? uk) : ru ? ruText : uk);
```

Третий аргумент необязателен нарочно: недописанная страница отдаёт украинский,
а не пустое место. Работа здесь механическая — дописать третий аргумент в 21 и
30 вызовов соответственно. Разметку не трогать вообще.

**`about`, `delivery`, `warranty`, `returns`, `contacts`** устроены иначе —
две копии разметки:

```tsx
{isRu ? (
  <>
    <h2>Новая Почта</h2>
    <ul>
      <li>Доставка 1–2 дня по Украине</li>
      …
    </ul>
  </>
) : (
  <>
    <h2>Нова Пошта</h2>
    …
  </>
)}
```

Третий язык в такой форме означал бы третью копию той же разметки — на returns
это ещё 60 строк JSX, которые дальше придётся править в трёх местах.
**Поэтому эти пять страниц сначала переводятся на хелпер `L()`, и только потом
получают английский.** Порядок именно такой: сначала рефакторинг без изменения
текста, потом перевод.

### Как конвертировать

Берётся **украинская** ветка как единственное дерево разметки. Русский текст
переезжает во второй аргумент `L()`, английский — в третий. Было:

```tsx
{isRu ? (
  <>
    <h2>Оплата</h2>
    <ul>
      <li>При получении (наложенный платёж)</li>
      <li>Monobank Acquiring</li>
    </ul>
  </>
) : (
  <>
    <h2>Оплата</h2>
    <ul>
      <li>При отриманні (накладений платіж)</li>
      <li>Monobank Acquiring</li>
    </ul>
  </>
)}
```

Стало:

```tsx
<h2>{L("Оплата", "Оплата", "Payment")}</h2>
<ul>
  <li>
    {L(
      "При отриманні (накладений платіж)",
      "При получении (наложенный платёж)",
      "Cash on delivery",
    )}
  </li>
  <li>Monobank Acquiring</li>
</ul>
```

Обратить внимание: «Monobank Acquiring» в `L()` не оборачивается — строка
одинакова во всех трёх языках, и оборачивать её значит добавить шум без пользы.
То же про телефон, адрес, названия брендов и моделей.

Если на странице ветвлений не было, а `L` ещё не объявлен — скопировать
объявление из `oferta/page.tsx` дословно, вместе с комментарием.

## 3. Отдельно: `generateMetadata`

Скрипт-чекер ловит `isRu ?` и в `generateMetadata` — поэтому на пяти страницах
с ветвлением заголовок и описание придётся перевести, чтобы проверка прошла.

**А на `oferta` и `privacy` чекер их не поймает**, потому что там переменная
называется `ru`, а не `isRu`. Их надо сделать руками, не забыть. Сейчас:

```tsx
const { locale } = await params;
const ru = locale === "ru";
return {
  title: ru ? "Публичная оферта и условия покупки" : "Публічна оферта та умови купівлі",
  description: ru ? "Условия покупки…" : "Умови купівлі…",
  alternates: pageAlternates(locale, "/oferta"),
};
```

Нужен третий вариант для `locale === "en"` у `title` и `description` на всех
семи страницах. `description` — 150–160 знаков, это текст в выдаче поиска.
`alternates` не трогать (см. §4, п. 4).

Ещё одно место того же рода — `returns/page.tsx:23`:

```tsx
const path = isRu ? "/ru/returns" : "/returns";
```

Для английской локали это даёт украинский путь. Починить вместе с остальным:
`/en/returns` для `en`.

## 4. Чего делать нельзя

Это важнее всего остального. Нарушение любого пункта хуже, чем непереведённая
страница.

1. **Не менять ни одной буквы украинского и русского текста.** Задача —
   добавить третий язык. Любая правка существующих текстов выходит за рамки и
   будет откачена вместе с полезной работой. Если видно опечатку — выписать её
   в конце отчёта, не править.
2. **Не менять разметку, классы и структуру.** После конвертации в `L()` дерево
   JSX обязано совпадать с украинской веткой до класса. Вёрстка этих страниц
   выверена, `info-page__panel` и утилитарные классы Tailwind оставить как есть.
3. **Не снимать `noindex` с `/en`.** В `src/app/[locale]/layout.tsx:35` стоит
   `robots: { index: false, follow: true }` для английской локали. Это нарочно:
   пока переведены не все страницы и не все описания товаров, отдавать `/en`
   в индекс нельзя — полупустая локаль роняет оценку всего домена. Снимут
   отдельным шагом, не в этой задаче.
4. **Не трогать `src/lib/seo-alternates.ts`.** Там `SiteLocale = "uk" | "ru"`,
   и `localizedPath("en", path)` возвращает украинский путь — то есть страницы
   `/en/*` сейчас объявляют канониклом украинский адрес. Это известно и при
   `noindex` безвредно; правка hreflang затрагивает все страницы сайта и делается
   отдельной задачей с проверкой в Search Console. В этой задаче — не касаться.
   Это же относится к `sitemap-data.ts`: английских адресов в карте сайта быть
   не должно, пока стоит `noindex`.
5. **Никаких превосходных степеней в английском тексте:** best, №1, unrivalled,
   world-leading, the most powerful. Аккаунт Merchant Center уже блокировали за
   «Искажение фактов» в сентябре 2026 — второй раз выйдет дороже, а политика
   читает весь сайт, не только фид.
6. **Не выдумывать условия.** Сроки доставки, проценты, суммы, сроки гарантии в
   английском тексте обязаны совпадать с украинским. Нет в украинском — нет и в
   английском.
7. **Не упоминать отзывы и рейтинги.** Их нет.
8. **Машинный перевод юридических формулировок не годится.** Смысл важнее
   гладкости: «накладений платіж» — это `cash on delivery`, а не
   `imposed payment`.

## 6. Юридическая оговорка на `oferta` и `privacy`

Английские версии этих двух страниц — перевод для удобства, а не самостоятельный
документ. В конце каждой добавить абзац, отдающийся **только** в английской
локали:

```tsx
{en && (
  <p>
    This English text is provided for convenience only. The Ukrainian version
    of this document is the legally binding one; in case of any discrepancy,
    the Ukrainian text prevails.
  </p>
)}
```

Оформление — по соседним абзацам страницы; своих классов не изобретать, взять
те, которыми уже набран мелкий служебный текст на этих двух страницах.
В украинской и русской версиях этого абзаца быть не должно.

## 7. `messages/en.json`

Часть текста этих страниц приходит не из JSX, а из словаря через
`getTranslations("pages")`, и там английский **уже есть**: `aboutTitle`,
`aboutText`, `aboutMilitaryTitle`, `aboutMilitaryP1…P3`, `aboutMilitaryCta`,
`aboutMilitaryGlory`, `deliveryTitle`, `deliveryText`, `warrantyTitle`,
`warrantyText`, `returnsTitle`, `contactsTitle`, `blogTitle`.

Эти ключи переводить заново не надо — проверить, что они подхватываются, и
не дублировать их текст в `L()`.

Если понадобится новый ключ, добавлять его **во все три** файла
(`messages/uk.json`, `messages/ru.json`, `messages/en.json`): наборы ключей
обязаны совпадать, иначе локаль без ключа отрендерит его имя вместо текста, и
заметно это будет только глазами на странице. Но предпочтительно новых ключей
не добавлять — текст этих страниц живёт в JSX, и так и задумано.

## 8. Критерии приёмки

Все четыре команды обязаны проходить. Выполнять из корня репозитория.

```bash
node scripts/check-en-pages.mjs
```
Должен вывести «все статические страницы переведены на английский» и выйти с
кодом 0. Это главный критерий: он означает, что ни одного вызова `L()` без
английского аргумента и ни одного ветвления `isRu` на этих страницах не
осталось.

```bash
npm run lint
```
Ноль ошибок. Типичная ошибка после такой правки — `'isRu' is assigned a value
but never used` или `'ru' is assigned a value but never used`: после удаления
последнего ветвления переменная остаётся объявленной. Удалять её, а не глушить
комментарием.

```bash
npm test
```
380 тестов, все проходят. Тесты эти страницы не покрывают, но они покрывают
`seo-alternates` и `product-name` — падение здесь означает, что задеты файлы,
которые задевать не следовало (см. §4, п. 4).

```bash
npm run build
```
Сборка без ошибок. `generateMetadata` возвращает типизированный `Metadata`,
и опечатка в поле всплывает только здесь.
