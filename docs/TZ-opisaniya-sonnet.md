# ТЗ: переписать описания товаров фида — порциями

Исполнитель — Claude в этом же чате (Claude Code, репозиторий
`internetstore-test`, браузер Claude in Chrome с открытой сессией админки).
Работа идёт **порциями по 10 товаров**. Всё состояние хранится в файлах, поэтому
её можно прервать в любой момент — лимит, выключенный компьютер — и продолжить
с того же места без потерь.

---

## 0. Зачем и сколько

В Google Merchant Center 493 товара: тепловизионные монокуляры, бинокли, ПНБ и
нейтральные аксессуары. Их описания писал генератор, и замер 05.10.2026 показал:

| Что не так | Товаров |
|---|---|
| Собрано из связок генератора («Головний орієнтир у цифрах», «У паспорті також є позиція»…) | 367 |
| Оружейная лексика («Для стрільби цього формфактора недостатньо», «сяде… на зброю») | 374 |
| «Так/Ні» вместо цифры («Окремо зазначено оптичне збільшення — Ні») | 213 |
| В русском тексте украинские слова («позиция «Тип батареї»») | 348 |
| Проходят все проверки | **104** |

Оружейная лексика уже стоила **15 заблокированных товаров** в Merchant Center
(политика «Огнестрельное оружие»). Сейчас сайт вырезает её при показе страницы
(`productPageDescription`), но тексты в базе остаются грязными. Шаблоны держат
товарные страницы на 4–10 месте в поиске.

**Цель:** все товары очереди (около 390, точное число покажет `init`)
переписаны и проходят проверку `scripts/description-batches.ts check`.

## 1. Нельзя — важнее всего остального

1. **Никаких слов про оружие и стрельбу.** Ни в каком виде, **включая
   отрицание**: «не для стрільби», «на зброю не ставлять», «для монтажу на
   карабін обирають приціл» — Google читает слова, а не смысл. Запрещены:
   зброя, приціл, стрільба, постріл, віддача, калібр, насадка, цівка, карабін,
   рушниця, а у приборов ещё и **кріплення, кронштейн, планка, рейка,
   Picatinny, Weaver** (и русские аналоги). Гнездо под штатив — не упоминать
   совсем, оно есть в таблице характеристик. Застёжку ремня называть
   «застібка», а не «карабін»: проверка не отличит её от оружия, и Google тоже.
   У аксессуаров слова «кріплення/кронштейн» можно, если это суть товара
   (адаптер на шолом), но оружия и стрельбы — нельзя. Если аксессуар —
   батарея к модели-прицелу, называйте **модель** (Pulsar Thermion 2), без слова
   «приціл».
2. **Только цифры из характеристик товара.** Каждое число в тексте должно быть
   в данных товара. Не вычислять: дальность ідентифікації из розпізнавання,
   поле зору в метрах из градусов, время работы из ёмкости. Grok делал именно
   так («ідентифікацію на 600 м» у ATN OTS-HD 640 — такой цифры нет). Нет
   цифры — нет темы.
3. **«Так/Ні» — не цифра.** Строку «Оптичне збільшення: Ні» либо пропустить,
   либо сказать по-человечески («збільшення тут цифрове»). Фраза, которая
   заканчивается на «— Ні.» / «: Так.», не пройдёт проверку.
4. **Без связок генератора.** Запрещены целиком: «Головний орієнтир у
   цифрах», «У паспорті також є», «Окремо зазначено», «Ще одна цифра з
   картки», «Бренд … у цій картці», «Усі висновки нижче», «Звіряйте
   комплектацію», «Для комплектації важливо, що», «розпізнавання силуету на
   практиці», «Перед замовленням порівняйте тип», «У лінійці», «Конструкція
   орієнтована» — и их русские двойники.
5. **Без превосходных степеней и отзывов:** найкращий, №1, ідеальний,
   найпотужніший, неперевершений, «за відгуками», рейтинг. Аккаунт уже
   блокировали за «Искажение фактов».
6. **Чистый язык.** В украинском тексте нет ы, э, ъ, ё; в русском нет і, ї,
   є, ґ. Подписи характеристик и названия переводить: «Тип батареи», а не «Тип
   батареї». Русское название товара брать из вывода `next` («название RU»).
7. **Не трогать ничего, кроме `descriptionUk` и `descriptionRu`.** Названия,
   цены, характеристики, фото, наличие — не менять. Товары вне очереди не
   трогать.
8. **Пароли не вводить никогда.** Если сессия админки закончилась (401 или
   страница входа) — остановиться и попросить пользователя войти самому.

## 2. Каким должен быть текст

**Длина** 1200–1800 знаков на каждом языке; держитесь около 1300–1500.
**3–4 абзаца**, между абзацами пустая строка (`\n\n` в JSON) — страница их
показывает. Без заголовков и списков.

1. **Что это и чем отличается** (2–3 предложения). **Модель в первом
   предложении**, тип прибора, главная цифра, задача.
2. **Что дают характеристики на практике** (3–5 предложений). Объяснять, а не
   перечислять: что даёт NETD в сырую погоду, что значит цифровой зум на
   максимуме, зачем светосила F1.0.
3. **Кому подойдёт и где ограничение** (2–3 предложения). Честно: вес, поле
   зрения, цифровой зум.
4. **Практическое** (1–2 предложения): питание, память, Wi-Fi, гарантия — если
   есть в характеристиках.

Украинский и русский — **один набор фактов, но каждый текст написан на своём
языке**, а не переведён калькой.

**Разнообразие.** Не начинайте предложения одинаково у разных товаров:
зачин из шести слов (цифры и модели не в счёт), повторённый больше чем у 5
товаров во всём каталоге, проверка отклонит. Команда `next` показывает уже
занятые зачины — их обходить.

**Образец** — `docs/descriptions-example-001.json` (Pulsar Telos LRF XQ35).
Он проходит проверку. Смотреть на него как на уровень, **фразы не копировать**:
одинаковые зачины проверка отловит.

## 3. Один раз в начале

### 3.1 Браузер и сессия

В Claude in Chrome создать свою вкладку, открыть
`https://pro-optics.com.ua/admin/news` и проверить сессию:

```js
(await fetch('/api/admin/products?limit=1')).status
```

`200` — работаем. Иначе — правило 1.8.

### 3.2 Выгрузка каталога

**Спросить у пользователя разрешение** на скачивание файла
`catalog-export.json` (2–4 МБ, выгрузка товаров из админки в папку
«Загрузки»). После «да» выполнить во вкладке админки:

```js
const all = [];
for (let page = 1; page < 50; page++) {
  const j = await (await fetch(`/api/admin/products?page=${page}&limit=100`)).json();
  all.push(...j.products);
  if (!j.products.length || all.length >= j.total) break;
}
const a = Object.assign(document.createElement('a'), {
  href: URL.createObjectURL(new Blob([JSON.stringify(all)], { type: 'application/json' })),
  download: 'catalog-export.json',
});
document.body.appendChild(a); a.click(); a.remove();
`${all.length} товаров`
```

### 3.3 Рабочая папка

```bash
mkdir -p ../descriptions-work && mv ~/Downloads/catalog-export.json ../descriptions-work/
npx tsx scripts/description-batches.ts init ../descriptions-work/catalog-export.json
```

Команды запускаются из корня репозитория (`internetstore-test`). Папка
`../descriptions-work` лежит рядом с ним и в git не попадает. `init` делает
нетронутый бэкап `backup-<дата>.json` и строит очередь. Если `init` пишет, что
`state.json` уже есть, — работа уже начата, переходите к разделу 4.

### 3.4 Первая партия — проверка конвейера на одном товаре

```bash
cp docs/descriptions-example-001.json ../descriptions-work/batches/001.json
npx tsx scripts/description-batches.ts check 1
```

Дальше шаги 4.4–4.5 для этой партии. Если всё прошло, Telos LRF XQ35 на сайте
с новым текстом, а конвейер проверен. Ничего не писать, пока это не прошло.

## 4. Порция — 10 товаров

### 4.1 Где мы

```bash
npx tsx scripts/description-batches.ts status
```

Если там «СТОП: партия NNN не доведена» — довести её (4.3–4.5), а не начинать
новую.

### 4.2 Данные

```bash
npx tsx scripts/description-batches.ts next 10
```

Выводит номер партии, характеристики 10 товаров и уже занятые зачины.

### 4.3 Написать и проверить

Записать файл `../descriptions-work/batches/NNN.json` (номер — из вывода
`next`) инструментом Write, **одним вызовом**:

```json
[
 { "slug": "…", "descriptionUk": "…", "descriptionRu": "…" }
]
```

```bash
npx tsx scripts/description-batches.ts check NNN
```

Если не прошла — исправить **только отмеченные предложения** (Edit), не
переписывая файл целиком, и запустить `check` снова. Если один товар не
проходит после трёх попыток — убрать его из файла партии (он останется в
очереди) и отметить в отчёте.

После прохождения `check` создаёт `batches/NNN.upload.json`.

### 4.4 Записать в базу

Во вкладке админки:

```js
document.getElementById('claude-up')?.remove();
const inp = Object.assign(document.createElement('input'), { type: 'file', id: 'claude-up' });
inp.setAttribute('aria-label', 'claude upload');
inp.style.cssText = 'position:fixed;top:0;left:0;opacity:0.01;width:10px;height:10px;z-index:99999';
document.body.appendChild(inp); 'ok'
```

Найти поле (`find`: «file input with aria-label claude upload»), положить в
него файл инструментом `file_upload` с путём к `NNN.upload.json`, затем:

```js
const items = JSON.parse(await document.getElementById('claude-up').files[0].text());
const errors = [];
for (const it of items) {
  const r = await fetch('/api/admin/products', {
    method: 'PUT',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ id: it.id, descriptionUk: it.descriptionUk, descriptionRu: it.descriptionRu }),
  });
  if (!r.ok) errors.push(`${it.slug}: ${r.status} ${(await r.text()).slice(0, 120)}`);
}
document.getElementById('claude-up').remove();
JSON.stringify({ total: items.length, errors })
```

В теле запроса **только** `id` и два описания — остальные поля API берёт из
базы (тип товара тоже, это исправлено в `2031585`). Ошибки — повторить для них
один раз; не прошло — остановиться и сообщить.

### 4.5 Отметить

```bash
npx tsx scripts/description-batches.ts apply NNN
```

`apply` открывает живые страницы товаров на обоих языках и сверяет, что там
новый текст. Только после этого отмечает партию сделанной и отправляет адреса
в IndexNow. Если пишет «на сайте ещё старый текст» — запись в базу не прошла,
вернуться к 4.4.

### 4.6 Отчёт и стоп

Одной строкой:

> Партия NNN: 10 товаров на сайте. Всего сделано X из N. Пропущено: … (если было).

**После каждой порции — стоп.** Пользователь пишет «дальше» — следующая
порция; «дальше 3» — три порции подряд.

---

## 5. Экономия лимита

- Это ТЗ прочитать один раз за сессию, не перечитывать перед каждой порцией.
- `next` — один раз на порцию. Не открывать `catalog.json` целиком: он большой.
- Партию писать одним вызовом Write, исправления — точечными Edit.
- В браузере — только `javascript_tool`, `find`, `file_upload`. Без скриншотов.
- Тексты не повторять в чате — они уже в файле.

---

## 6. Когда всё сделано

`status` покажет «осталось 0». Тогда:

1. Свежая выгрузка (3.2) и итоговая проверка всего фида:
   ```bash
   npx tsx scripts/check-descriptions.ts ~/Downloads/catalog-export.json --feed
   ```
   Ожидается «партия прошла проверку». Что не прошло — список в отчёт.
2. Сказать пользователю, что можно проверить Merchant Center: заблокированных
   по «Огнестрельному оружию» быть не должно.

Фильтр `productPageDescription` на сайте **не убирать** — он страхует от
следующей массовой правки.
