# Hard-аудит: Johnson / видно–не видно (2026-07-30)

## Проблема, яку закрили

Раніше **бейдж статусу** (Ідентифікація / Розпізнавання / Виявлення) рахувався за  
`px = 2×(D/dist)`, а **розмір оленя на екрані** — окремою геометрією `0.52×(50/d)`.

Через це:

- при тому ж `dist` status і «скільки пікселів реально на матриці» **роз’їжджались**;
- 256 vs 640 мали **однаковий** статус (ok) і **однаковий** фізичний розмір на логічному canvas (погано для відчуття матриці);
- на межі D («Виявлення») ціль могла виглядати інакше, ніж «≈2 px».

## Рішення (зараз)

### 1. Статус (як і раніше, чіткі пороги)

| px на цілі | Статус | Сенс |
|------------|--------|------|
| **≥ 13** | Ідентифікація | видно деталі |
| **≥ 8** | Розпізнавання | зрозуміло, що тварина |
| **≥ 2** | Виявлення | видно, що щось є |
| **&lt; 2** | Не видно | зливається з шумом |

```
px = 2 × (D / dist)     // dist = D → px = 2
туман: px × 0.6
```

Пороги дистанції (ясно):

| Статус | max dist |
|--------|----------|
| ідентифікація | ≤ 2D/13 ≈ D/6.5 |
| розпізнавання | ≤ D/4 |
| виявлення | ≤ D |

### 2. Картинка синхронізована з Johnson

Після downscale матриці **висота оленя на сенсорі ≈ px**:

```
frac = px / pixH
deerH_logic = frac × logicH
```

де `pixH = matrixPixelHeight(matrix)` (96/144/240 wide × 9/16).

Перевірка unit-тестами:

- dist=D → sensor height ≈ **2**
- dist=D/4 → ≈ **8**
- dist=2D/13 → ≈ **13**

### 3. UI

Над кожною панеллю:

- badge + **пояснення** («видно деталі ≥13 px» …)
- `Johnson X.X px · на матриці ≈ Y.Y px` (мають збігатися)
- смуги: ідентиф. ≤ A м · розпізн. ≤ B м · виявл. ≤ C м

### 4. Що **не** ламає статус

| Параметр | Вплив на badge | Вплив на картинку |
|----------|----------------|-------------------|
| D | ✅ калібрує px | ✅ через px |
| dist | ✅ | ✅ |
| fog | ✅ ×0.6 | ✅ |
| matrix | ❌ (grain only у старій моделі; **тепер** розмір через pixH) | ✅ зерно + frac |
| NETD | ❌ | шум |
| digi-zoom | ❌ | тільки зум блоків |
